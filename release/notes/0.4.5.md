## 0.4.5

- Add 12 direct MCP tools for instance discovery/selection, database metadata, function lookup/search/decompilation/disassembly, callers/callees, xrefs, strings and memory reads. Keep all 11 domain tools and their typed method contracts.
- Simplify public input schemas and return correctable tool errors with field issues and recovery hints. JSON text and structured results match.
- Allow direct reads to use the selected or sole available instance; require an explicit choice when several databases are available.
- Add bounded per-instance FIFO waiting: 2 active requests, up to 8 waiting requests, and at most 5 seconds of queue waiting. Retry only explicitly retryable read-only IDA_BUSY, up to twice under one overall deadline.
- Keep writes, scripts and debugger control single-execution. Side-effecting timeouts report an unknown outcome and advise checking IDA state before resubmission.
- Add optional -diagnostics stderr metadata and a no-IDA compatibility verifier for four protocol versions over stdio and HTTP. Update packaged skills and bilingual public usage guides.

**Client migration:** Restart the Gateway and reconnect the client to refresh tools, skills and allowlists. Direct tools take top-level operation parameters and return the operation result; existing domain tools retain list/describe/call and the method/result envelope. A busy or timeout response does not justify automatically repeating side-effecting operations. Protocol and SDK checks do not replace real Agent/model or licensed IDA integration tests.

- 增加 12 个常用直接 MCP 工具，覆盖实例发现/选择、数据库信息、函数查询/搜索/反编译/反汇编、调用关系、交叉引用、字符串及内存读取，保留原有 11 个领域工具与 typed 方法合同。
- 简化公开输入 schema；参数错误返回具体字段、预期合同和恢复提示，JSON 文本与结构化结果保持一致。
- 直接读取可使用已选实例或唯一可用实例；多个数据库时仍需明确选择。
- 每实例保持 2 个执行槽，增加最多 8 个等待请求、最长 5 秒的 FIFO 队列；仅对只读且明确可重试的 IDA_BUSY 最多重试两次，所有尝试共用总期限。
- 修改、脚本和调试控制保持单次执行；有副作用操作超时提示执行结果未知，重提之前需检查实际 IDA 状态。
- 增加可选 -diagnostics stderr 元数据及四协议版本的 stdio/HTTP 无 IDA 兼容性验证；更新包内技能和中英文公开使用文档。

**客户端迁移：** 重启 Gateway 并重连客户端，刷新工具目录、技能和允许列表。直接工具接收顶层业务参数并返回业务结果；领域工具保持 list/describe/call 与 method/result 包装。忙碌或超时不代表可以自动重复有副作用操作；协议和 SDK 检查不能代替真实 Agent/模型或需要许可的 IDA 联调。
